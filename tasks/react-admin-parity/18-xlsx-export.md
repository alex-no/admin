## 🔴 Рекомендація: не робити

Описано для повноти пакету; **рекомендація — скасувати**, якщо не з'явиться
конкретна причина. Обґрунтування нижче.

### Чому не варто

1. **Наш CSV уже коректно відкривається в Excel.** `utils/csv.js` додає
   **UTF-8 BOM** (`return '﻿' + lines.join('\r\n')`) саме для цього — без
   BOM Excel ламає кирилицю. Плюс `\r\n` як розділювач рядків і правильне
   екранування лапок/коми/точки з комою (`escapeCsvField`). Тобто головна
   причина хотіти XLSX — «кирилиця в кракозябрах» — уже закрита.

2. **react-admin теж віддає CSV.** Його дефолтний `exporter` використовує
   `jsonexport` → CSV. XLSX там — кастомний exporter, який пише сам розробник.
   Тобто це не «фіча react-admin, якої в нас немає», а «те, що в react-admin теж
   треба робити руками».

3. **Ціна — нова залежність у бандлі.** `xlsx` (SheetJS) ~ сотні КБ, `exceljs`
   ще більше. Адмінка зараз має рівно чотири рантайм-залежності поза Vue
   (bootstrap, leaflet, fullcalendar, socket.io-client — останні дві в адмінці
   навіть не використовуються). Додавати важку бібліотеку заради формату, який
   вирішує ту саму задачу, що вже вирішена, — погана угода.

4. **Форматування, за яке платять, нам не потрібне.** XLSX виграє, коли треба
   типи клітинок, кілька листів, ширини колонок, заморожені заголовки, формули.
   Наш експорт — плоска вигрузка списку для подальшої обробки
   (`EXPORT_COLUMNS` у `Users.vue:861-869` — сім текстових колонок).

### Коли варто переглянути

- якщо потрібні **кілька листів** в одному файлі (напр. СТО + їх послуги
  окремим листом);
- якщо потрібні **типи клітинок** (дати як дати, числа як числа) — щоб Excel не
  перетворював `+380...` у число або `01.02` у дату;
- якщо вигрузку відкривають не в Excel, а імпортують у систему, що вимагає XLSX.

**Дешевша альтернатива, що закриває пункт «типи клітинок»:** не міняти формат, а
поправити CSV — обгортати телефони й коди в `="..."`, щоб Excel не приводив їх
до числа. Це правка одного `escapeCsvField` замість нової залежності. Якщо
задачу вирішено робити — почати з цього.

## Технічні деталі

### Поточний `escapeCsvField` (utils/csv.js)

```js
function escapeCsvField(value) {
  const str = value === null || value === undefined ? '' : String(value)
  if (/["\n\r,;]/.test(str)) {
    return `"${str.replace(/"/g, '""')}"`
  }
  return str
}
```

Правка під `raw`:

```js
/**
 * @param {*} value
 * @param {boolean} [raw] - true для полів, які Excel не має приводити до типу
 *   (телефони, VIN, ISO-коди, значення з провідними нулями). Обгортка ="..."
 *   змушує Excel трактувати клітинку як текст.
 */
function escapeCsvField(value, raw = false) {
  const str = value === null || value === undefined ? '' : String(value)
  if (raw && str !== '') {
    return `="${str.replace(/"/g, '""')}"`
  }
  if (/["\n\r,;]/.test(str)) {
    return `"${str.replace(/"/g, '""')}"`
  }
  return str
}
```

⚠️ `rowsToCsv(headers, rows)` приймає плоскі масиви значень — щоб передати
`raw` по колонках, потрібен третій аргумент із дескрипторами, напр.
`rowsToCsv(headers, rows, { raw: [false, false, true, ...] })`. Не міняти підпис
несумісно: сторінок з експортом уже 7.

⚠️ `="..."` — це excel-специфіка. У чистому CSV-парсері (pandas, `csv` у Python)
значення прийде як `="+380..."`. Тому позначати `raw` **тільки** там, де
автоприведення реально шкодить, а не всі текстові колонки підряд.

## Scope & Non-Goals

**В scope (варіант CSV):** прапорець `raw`, розстановка по `EXPORT_COLUMNS` на 7
сторінках, розкатка експорту на сторінки без нього.

**В scope (варіант XLSX):** `utils/xlsx.js`, динамічний імпорт `xlsx`, типи
клітинок, дропдаун експорту.

**Поза scope обох:** серверна генерація файлів, кілька листів, формули, стилі,
PDF-експорт, заміна CSV.

## FAQ

**Q: Чому це окрема задача, якщо рекомендація — не робити?**
A Щоб рішення було зафіксоване. У [STATUS.md](STATUS.md) вона стоїть із
пропозицією «скасувати» — але з готовим планом на випадок, якщо з'явиться
конкретна потреба (кілька листів або типи клітинок).

**Q: Наш CSV точно відкривається в Excel без проблем із кирилицею?**
A Так, і це не випадково: `utils/csv.js` явно додає UTF-8 BOM з коментарем
«щоб Excel правильно розпізнав кирилицю без ручного вибору кодування». Тобто
проблема була відома й уже вирішена.

**Q: Чи не краще генерувати файл на бекенді?**
A Ні. Поточна схема (`exportCsv()` пагінує list-ендпоінт і збирає файл у
браузері) переиспользует наявний API й уже дотримується прав доступу. Серверна
генерація означала б новий ендпоінт на кожен ресурс і дублювання логіки фільтрів.

**Q: А PDF?**
A Поза scope і не рекомендую: PDF потрібен для друку звітів, а не для вигрузки
даних. Якщо знадобиться друк — це задача про `@media print`, не про експорт.
