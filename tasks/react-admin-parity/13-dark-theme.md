## Контекст

Тёмної теми в адмінці немає взагалі — жодного `prefers-color-scheme`, жодного
перемикача, жодної змінної теми (`grep -ril "dark-mode\|darkMode\|prefers-color-scheme\|toggleTheme"` по
`www_front/admin/src` → нічого). Адмін, що працює в адмінці кілька годин на день
у темному оточенні, дивиться на білий екран.

react-admin має `<ToggleThemeButton>` і пару `lightTheme`/`darkTheme` з коробки.

### Чому це дешевше, ніж здається

Bootstrap 5.3 (у нас `^5.3.8`) має **вбудовану** підтримку кольорових режимів
через атрибут `data-bs-theme="dark"` на `<html>`. Усі утилітарні класи
(`bg-light`, `table-light`, `text-muted`, `card`, `dropdown-menu`, `form-control`,
`badge`) перемальовуються самі, без правок розмітки. Тобто базово тема
включається одним атрибутом.

### Чому це дорожче, ніж здається

Кастомні кольори, захардкожені в `<style scoped>` по компонентах, Bootstrap не
знає і не перемалює. Фактичний обсяг:

| Колір | Входжень | Що це |
|---|---|---|
| `#dee2e6` | 26 | бордюри |
| `#f8f9fa` | 25 | світлий фон (той самий, що `bg-light`) |
| `#e9ecef` | 17 | фон-заповнювач |
| `#86b7fe` | 10 | focus-бордюр (напр. `.inline-editable:hover`) |
| `#fff` / `#ffffff` | 6 | білий фон |
| `#666`, `#6c757d` | 9 | сірий текст |
| `#0d6efd` | 5 | primary |
| решта (`#ffc107`, `#dc3545`, `#ff9800`, `#fd7e14`, `#e9f0ff`, `#e8f0fe`) | 8 | акценти/підсвітки |

Разом ~106 входжень. Плюс інлайнові `style="background:#fff"` — напр. у
`pages/Users.vue:168` (`background:#fff` на tab-nav модалки).

Тобто задача = «увімкнути `data-bs-theme` + вичистити ~106 захардкожених
кольорів у CSS-змінні».

## Промпт для Claude Code

> Додай тёмну тему в адмінку — аналог `<ToggleThemeButton>` з react-admin, на
> базі вбудованого в Bootstrap 5.3 механізму `data-bs-theme`.
>
> 1. **Новий composable `www_front/admin/src/composables/useTheme.js`**:
>    - три стани: `'light'` / `'dark'` / `'auto'` (за системним
>      `prefers-color-scheme`);
>    - виставляє `data-bs-theme` на `document.documentElement`;
>    - зберігає вибір у `localStorage` (`admin.theme`);
>    - у режимі `'auto'` слухає `window.matchMedia('(prefers-color-scheme: dark)')`
>      і перемальовується при зміні системної теми.
>
> 2. **Застосовувати тему до першого рендера.** Інакше буде «біле блимання» при
>    завантаженні. Атрибут виставляти інлайновим скриптом у
>    `www_front/admin/index.html`, до підключення бандла, читаючи
>    `localStorage.getItem('admin.theme')`.
>
> 3. **Перемикач у `components/TopNav.vue`** — у блок користувача, поруч із
>    дропдауном профілю: іконка `bi-sun` / `bi-moon-stars` / `bi-circle-half`,
>    цикл light → dark → auto.
>
> 4. **Вичистити захардкожені кольори.** Замінити ~106 входжень hex-кольорів у
>    `<style scoped>` на CSS-змінні Bootstrap, які самі перемикаються:
>    - `#f8f9fa` → `var(--bs-secondary-bg)` (або `var(--bs-tertiary-bg)` для
>      заповнювачів)
>    - `#dee2e6` → `var(--bs-border-color)`
>    - `#e9ecef` → `var(--bs-tertiary-bg)`
>    - `#fff` / `#ffffff` → `var(--bs-body-bg)`
>    - `#666` / `#6c757d` → `var(--bs-secondary-color)`
>    - `#0d6efd` → `var(--bs-primary)`
>    - `#86b7fe` → `var(--bs-primary-border-subtle)`
>    - акценти (`#ffc107`, `#dc3545`, `#fd7e14`, `#ff9800`) → відповідні
>      `var(--bs-warning)` / `var(--bs-danger)` / `var(--bs-orange)`; де це
>      власна семантика (підсвітка нового рядка) — завести власну змінну з
>      значеннями під обидві теми
>    - `#e9f0ff`, `#e8f0fe` (підсвітки виділення/новизни) → власні змінні,
>      напр. `--admin-highlight-bg`, визначені для обох тем
>
> 5. **Інлайнові `style` з кольорами теж вичистити** — напр. `background:#fff`
>    у tab-nav модалки (`pages/Users.vue:168`) і аналогічні в інших модалках.
>    Їх Bootstrap не перемалює, і в темній темі вони дадуть білу смугу.
>
> 6. **Перевірити всі 26 списковых сторінок + усі модалки в темній темі
>    очима.** Це не той тип задачі, який закривається без візуальної перевірки:
>    контраст бейджів, читабельність `text-muted` на темному, видимість
>    бордюрів таблиці, focus-стани інпутів.
>
> 7. **Графіки** (`components/BarChart.vue`, `PieChart.vue`, `TrendChart.vue`,
>    `HourlyChart.vue`) — перевірити окремо: якщо кольори осей/підписів
>    захардкожені, вони зникнуть на темному фоні.
>
> 8. **Leaflet-карта** (якщо використовується в адмінці) — тайли залишаються
>    світлими, це нормально; але контейнер, контроли й попапи мусять читатись.
>
> **Не робити:** власну палітру поверх Bootstrap, темну тему для основного
> фронтенду (`www_front/src`) — це окрема задача й окрема аудиторія, перемикач
> теми на сторінці логіну (тема застосовується, перемикач — після входу).

## Технічні деталі для імплементації

### 1. `useTheme.js`

```js
import { ref, watch } from 'vue'

const STORAGE_KEY = 'admin.theme'
const MODES = ['light', 'dark', 'auto']

// Модульний singleton — той самий підхід, що useAuth.js / useNotify.js.
const mode = ref(read())

function read() {
  const v = localStorage.getItem(STORAGE_KEY)
  return MODES.includes(v) ? v : 'auto'
}

function systemPrefersDark() {
  return window.matchMedia('(prefers-color-scheme: dark)').matches
}

function resolved() {
  return mode.value === 'auto' ? (systemPrefersDark() ? 'dark' : 'light') : mode.value
}

function apply() {
  document.documentElement.setAttribute('data-bs-theme', resolved())
}

watch(mode, (v) => { localStorage.setItem(STORAGE_KEY, v); apply() })

// У режимі auto слухаємо системну тему — інакше адмін перемкне тему ОС і
// побачить зміну лише після F5.
window.matchMedia('(prefers-color-scheme: dark)').addEventListener('change', () => {
  if (mode.value === 'auto') apply()
})

export function useTheme() {
  function cycle() {
    mode.value = MODES[(MODES.indexOf(mode.value) + 1) % MODES.length]
  }
  return { mode, resolved, cycle, apply }
}
```

### 2. Анти-блимання в `index.html`

```html
<script>
  // Виставляємо тему до завантаження бандла — інакше в темному режимі буде
  // біле блимання на час парсингу JS.
  (function () {
    var m = localStorage.getItem('admin.theme') || 'auto';
    var dark = m === 'dark' || (m === 'auto' &&
      window.matchMedia('(prefers-color-scheme: dark)').matches);
    document.documentElement.setAttribute('data-bs-theme', dark ? 'dark' : 'light');
  })();
</script>
```

⚠️ Ключі `localStorage` в цьому скрипті й у composable мусять збігатись
дослівно — це два незалежних місця з однією константою. Найдешевша страховка:
коментар у composable з посиланням на `index.html`.

### 3. Власні змінні для того, що Bootstrap не покриває

Частина кольорів — не «сірий фон», а власна семантика: підсвітка щойно
створеного рядка (`justCreatedIds`), hover inline-редагування, підсвітка
виділення. Для них — власні змінні в глобальному стилі адмінки:

```css
:root,
[data-bs-theme="light"] {
  --admin-highlight-bg: #e9f0ff;   /* щойно створений рядок */
  --admin-inline-hover-bg: #f8f9fa;
}

[data-bs-theme="dark"] {
  --admin-highlight-bg: #1c2a44;
  --admin-inline-hover-bg: #2b3035;
}
```

Значення для темної теми підбирати **очима**, а не арифметичною інверсією —
інвертований `#e9f0ff` дає брудно-жовтий.

### 4. Пастки, які варто перевірити цілеспрямовано

- **`text-dark` без пари.** 65 входжень. У Bootstrap 5.3 `text-dark` це
  «темний текст», і в темній темі він залишається темним. Там, де він стоїть на
  `bg-warning`/`bg-light` (`badge bg-warning text-dark` — типовий патерн у
  бейджах статусів) — усе гаразд, бо фон теж світлий. Там, де сам по собі —
  замінити на `text-body`.
- **`table-light` у `<thead>`.** 36 входжень. Bootstrap перемалює, але контраст
  із `table-hover` варто перевірити.
- **`navbar-dark bg-dark` у `TopNav.vue:2`.** У світлій темі навбар темний за
  дизайном. У темній він зіллється з фоном сторінки — потрібен бордюр знизу або
  трохи інший відтінок.
- **`spinner-border text-primary`** на темному — перевірити видимість.
- **Графіки.** Якщо кольори осей задані через SVG-атрибути або хардкод у JS —
  вони не змінюються від CSS-змінних. Може знадобитись передавати колір із
  `resolved()`.

### 5. Порядок робіт

1. `useTheme.js` + скрипт в `index.html` + перемикач у `TopNav.vue`. Перемкнути
   в dark — усе, що на утилітарних класах Bootstrap, уже виглядає прийнятно.
2. Пройти по списку hex-кольорів (`grep`) і замінити на змінні — файл за файлом.
3. Візуальний прохід по 26 сторінках і модалках, фікси того, що знайдеться.
4. Графіки й карта окремо.

## Scope & Non-Goals

**В scope:** composable, анти-блимання, перемикач, заміна ~106 hex-кольорів на
змінні, власні змінні для семантичних підсвіток, візуальна перевірка всіх
сторінок і модалок, графіки.

**Поза scope:**
- власна палітра / кастомна тема поверх Bootstrap
- темна тема для `www_front/src` (основний фронтенд)
- перемикач теми до входу (тема застосовується, перемикач після логіну)
- темні тайли карти
- висококонтрастна тема / інші accessibility-режими

## FAQ

**Q: Чому `data-bs-theme`, а не власний клас `.dark` і повна палітра?**
A Тому що Bootstrap 5.3 уже вміє це для всіх своїх компонентів. Власна палітра
означала б переписати кольори `card`, `dropdown`, `form-control`, `table`,
`badge`, `alert`, `modal` — тобто зробити руками те, що вже є у фреймворку.

**Q: Чому три режими, а не два?**
A `auto` — це те, що очікується за замовчуванням (стежить за ОС), а явні
`light`/`dark` потрібні, коли адмін хоче зафіксувати незалежно від системи.
react-admin теж має цю трійку.

**Q: 106 кольорів — це обов'язково, чи можна включити тему й вичищати поступово?**
A Технічно тема запрацює й без вичищення, але виглядатиме зламано: світлі плями
`#f8f9fa`/`#fff` на темному фоні. Мінімум, без якого не варто вважати задачу
зробленою: `#fff`/`#ffffff`, `#f8f9fa`, `#dee2e6`, `#e9ecef` — це 74 з 106
входжень і майже всі видимі плями.

**Q: Чи не зламає це існуючу верстку в світлій темі?**
A Заміна `#f8f9fa` на `var(--bs-secondary-bg)` у світлій темі дає **той самий**
колір — це і є значення змінної в light-режимі. Тобто світла тема мусить
залишитись піксельно тією ж; якщо щось змінилось — підставлена не та змінна.
