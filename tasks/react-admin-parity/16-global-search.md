## Контекст

Пошук у нас є на кожній сторінці окремо — `?search=` у своєму list-ендпоінті. Але
щоб знайти щось, не знаючи, де воно лежить, адмін мусить угадати сторінку.
Типовий сценарій: телефон або email прийшли в зверненні, і незрозуміло, це
користувач, менеджер СТО чи контакт самого СТО — треба перевірити три сторінки
руками.

react-admin має для цього enterprise-компонент `<Search>` у `<AppBar>`:
один інпут, результати згруповані по ресурсах, клік веде на запис.

## Промпт для Claude Code

> Додай глобальний пошук по ресурсах в адмінку — аналог `<Search>` з
> react-admin enterprise.
>
> ### Backend
>
> 1. **Новий ендпоінт `GET /api/admin/search?q=...`** і новий контролер
>    `www_app/src/Module/Admin/Api/Controller/AdminSearchController.php`.
>    Роут — у `config/common/routes.php`, поруч із рештою `/api/admin/*`.
>
> 2. **Відповідь згрупована по ресурсах:**
>    ```json
>    {
>      "status": "success",
>      "data": {
>        "sto":   { "total": 3, "items": [ { "id": 42, "label": "СТО Автопрофі", "hint": "Львів, вул. Зелена 12" } ] },
>        "users": { "total": 1, "items": [ { "id": 7, "label": "ivan@example.com", "hint": "Іван Петренко" } ] },
>        "cities":{ "total": 0, "items": [] }
>      }
>    }
>    ```
>    `label` — те, що показати; `hint` — уточнення другим рядком; `total` —
>    скільки всього (для «показати всі»).
>
> 3. **Ресурси й поля пошуку — явний реєстр у контролері, не динамічний.**
>    Кожен ресурс описується: таблиця, колонки для `LIKE`, як зібрати `label` і
>    `hint`, потрібне permission, куда веде посилання. Мінімальний набір:
>
>    | Ресурс | Шукати по | Permission |
>    |---|---|---|
>    | `sto` | `name_uk`, `name_en`, `name_ru` | `sto.view` |
>    | `users` | `username`, `email`, `firstname`, `lastname`, `phone` | `users.view` |
>    | `cities` | `name_uk`, `name_en`, `name_ru` | `geography.cities.view` |
>    | `car_models` | назва моделі + марка | `catalog.car-models.view` |
>    | `services` | `name_uk`, `name_en`, `name_ru` | `catalog.services.view` |
>    | `feedback` | текст звернення, контакт | `feedback.view` |
>    | `reviews` | текст відгуку | `reviews.view` |
>
> 4. **Права перевіряти по кожному ресурсу окремо**, і ресурси без права
>    **не включати у відповідь узагалі** — не порожніми, а відсутніми. Адмін не
>    мусить дізнаватись про існування ресурсу з того, що по ньому «0
>    результатів».
>
> 5. **Ліміт 5 записів на ресурс** у відповіді + `total` для «показати всі».
>    Загальний таймаут: якщо запит по ресурсу довше ~300мс — краще віддати
>    частковий результат, ніж чекати всі сім.
>
> 6. **Мінімальна довжина запиту — 2 символи.** Коротше — 400 або порожній
>    результат, без запитів до БД.
>
> 7. **Rate limiting.** Ендпоінт викликається на кожне натискання клавіші (з
>    дебаунсом). У проєкті вже є `RateLimiter` (див.
>    `docs/SECURITY_RATE_LIMITING.md`) — підключити його до цього роуту, а не
>    залишати відкритим.
>
> ### Frontend
>
> 8. **Новий компонент `www_front/admin/src/components/GlobalSearch.vue`** —
>    інпут у `TopNav.vue` (по центру або перед блоком користувача), дропдаун із
>    результатами, згрупованими по ресурсах із заголовками груп.
>
> 9. **Дебаунс 300мс + `AbortController`** — та сама механіка, що в
>    `useReferenceSearch` із задачі **09**. Якщо 09 уже зроблена, переиспользувати
>    її, а не писати другу копію.
>
> 10. **Клік по результату веде на сторінку ресурсу з відкритим записом** —
>     `/users?id=7`. Це вже працює: `useUrlFilters` читає `?id=` і викликає
>     `detail.onOpen` (`useUrlFilters.js:114-122`), а `Users.vue` умієь
>     довантажити запис, якого немає на поточній сторінці
>     (`Users.vue:738-757`). Для ресурсів, де `detail` у `useUrlFilters` ще не
>     налаштований, — налаштувати.
>
> 11. **Клавіатура:** фокус по `/` або `Ctrl+K` (глобальний хоткей), ↑/↓ по
>     результатах, Enter — перейти, Esc — закрити.
>
> **Не робити:** повнотекстовий індекс (Elasticsearch/Meilisearch/MySQL
> FULLTEXT), пошук по історії змін (`audit_log`), збереження історії пошуку,
> нечіткий пошук / виправлення опечаток, пошук по вкладених сущностях СТО
> (послуги, зручності, фото).

## Що перевірити після виконання

### Backend

- [ ] `GET /api/admin/search?q=` працює, роут зареєстрований у `config/common/routes.php`
- [ ] Відповідь згрупована по ресурсах, кожен елемент має `id`, `label`, `hint`
- [ ] **Ресурси без права відсутні у відповіді** (не порожні, а взагалі немає) — перевірити роллю без `sto.view`: ключа `sto` в JSON немає
- [ ] Реєстр ресурсів явний, у коді контролера; додавання ресурсу = один запис у реєстрі
- [ ] Ліміт 5 записів на ресурс; `total` показує реальну кількість
- [ ] `q` коротше 2 символів → жодного запиту до БД
- [ ] `q` з `%` і `_` не ламає `LIKE` — символи екрануються (інакше `%` віддає всю таблицю)
- [ ] SQL-інʼєкція неможлива: `q` іде bind-параметром, назви таблиць/колонок — з реєстру, не з запиту
- [ ] Rate limiting підключений — перевірити серією швидких запитів, мусить прийти 429
- [ ] Пошук по телефону знаходить користувача (перевірити з `+380` і без)
- [ ] Пошук по email знаходить користувача
- [ ] Пошук по назві знаходить і СТО, і місто, і послугу — тобто кілька груп в одній відповіді
- [ ] Час відповіді на порожній БД і на реальній прийнятний; частковий результат при таймауті замість зависання

### Frontend

- [ ] `GlobalSearch.vue` в `TopNav.vue`, видно на всіх сторінках з меню
- [ ] Дебаунс: швидке введення дає один запит, не шість
- [ ] `AbortController` скасовує попередній запит — результати не переганяють один одного
- [ ] Якщо задача **09** зроблена — механіка дебаунсу/скасування переиспользована, а не дубльована
- [ ] Групи результатів мають заголовки з назвою ресурсу
- [ ] «Показати всі N» веде на сторінку ресурсу з `?search=<q>` у URL
- [ ] Клік по результату веде на `/<resource>?id=<id>` і **модалка запису реально відкривається** — перевірити на записі, якого немає на першій сторінці списку
- [ ] Для ресурсів без налаштованого `detail` у `useUrlFilters` — налаштовано, модалка відкривається
- [ ] `Ctrl+K` / `/` фокусує інпут; `/` **не** перехоплюється, коли фокус в іншому інпуті або в модалці
- [ ] ↑/↓/Enter/Esc працюють

## Технічні деталі для імплементації

### 1. Реєстр ресурсів

Ключова частина — щоб додавання ресурсу було одним записом, а не новим методом:

```php
/**
 * Реєстр ресурсів глобального пошуку. Свідомо явний, а не побудований із
 * config-файлів: пошукові колонки й формат label/hint — це рішення про UX, а не
 * похідне від схеми. Назви таблиць і колонок беруться тільки звідси, ніколи з
 * запиту — тому підстановка їх у SQL як ідентифікаторів безпечна.
 */
private const RESOURCES = [
    'users' => [
        'table'      => 'user',
        'permission' => 'users.view',
        'columns'    => ['username', 'email', 'firstname', 'lastname', 'phone'],
        'label'      => "COALESCE(NULLIF(email, ''), username)",
        'hint'       => "TRIM(CONCAT_WS(' ', lastname, firstname))",
        'route'      => '/users',
    ],
    // ...
];
```

### 2. Екранування `LIKE`

```php
// %  і _ у LIKE — це вайлдкарди. Без екранування запит «%» віддає всю таблицю,
// а «_» матчить будь-який символ. Це не інʼєкція, але результат сміттєвий.
$escaped = addcslashes($q, '%_\\');
$like    = "%{$escaped}%";
```

⚠️ `addcslashes` + `LIKE ... ESCAPE '\\'` — перевірити, що MySQL-режим це
приймає; альтернатива `str_replace(['%', '_'], ['\%', '\_'], $q)`.

### 3. Частковий результат при таймауті

Сім послідовних запитів по 100-300мс = до 2 секунд на кожне натискання клавіші.
Мітигації, в порядку простоти:

1. **Ліміт 5 + індекси** на пошукових колонках. Перевірити по
   `bak/db-data/structure.sql`, чи вони є на `user.email`, `user.phone`,
   `city.name_uk` тощо; якщо ні — окрема міграція, і це найбільший виграш.
2. **Обмежити набір ресурсів** у першій версії до трьох найпотрібніших
   (`users`, `sto`, `cities`), решту додавати після заміру.
3. Не робити паралельних запитів через `Fiber`/async — PHP тут не допоможе,
   а складність зросте.

### 4. Хоткей `/` — типова пастка

```js
function onKeydown(e) {
  if (e.key === 'k' && (e.ctrlKey || e.metaKey)) { e.preventDefault(); focusSearch(); return }
  if (e.key !== '/') return
  // Не перехоплювати «/», якщо адмін пише в полі — інакше неможливо ввести
  // слеш у назві, в inline-редагуванні клітинки або в пошуку сторінки.
  const t = e.target
  if (t.tagName === 'INPUT' || t.tagName === 'TEXTAREA' || t.isContentEditable) return
  e.preventDefault()
  focusSearch()
}
```

⚠️ Перевірити взаємодію з `BaseModal`: коли модалка відкрита, глобальний хоткей
не мусить забирати фокус із неї.

### 5. Посилання на запис

Схема `/<resource>?id=<id>` працює завдяки `useUrlFilters`:

```js
detail: {
  id: detailId,
  onOpen: async (id) => { /* довантажити й відкрити модалку */ }
}
```

`Users.vue:736-757` уже реалізує повний варіант — з довантаженням запису, якого
немає на поточній сторінці. Для ресурсів, де `detail` не налаштований, взяти цей
код за референс.

⚠️ Без `onOpen`-довантаження глобальний пошук майже не працює: знайдений запис
рідко буває на першій сторінці списку.

## Scope & Non-Goals

**В scope:** новий контролер + роут, реєстр ресурсів, права по ресурсу, ліміти,
екранування `LIKE`, rate limiting, `GlobalSearch.vue`, хоткеї, налаштування
`detail.onOpen` там, де його немає.

**Поза scope:**
- повнотекстовий індекс (Elasticsearch, Meilisearch, MySQL FULLTEXT)
- нечіткий пошук / виправлення опечаток
- пошук по `audit_log`
- історія пошукових запитів
- пошук по вкладених сущностях СТО (послуги, зручності, адреси, фото)
- підсвітка збігів у результатах

## FAQ

**Q: Чому не MySQL FULLTEXT одразу?**
A `LIKE '%...%'` із лімітом 5 на ресурс і індексами на колонках достатній для
адмінських обсягів, і не вимагає ні міграцій під `FULLTEXT`, ні окремої логіки
релевантності. FULLTEXT має сенс, коли `LIKE` почне гальмувати — тоді це окрема
задача з заміром «до».

**Q: Чому ресурси без права зовсім відсутні, а не порожні?**
A Порожня група «СТО (0)» повідомляє адміну, що ресурс «СТО» існує, — це
дрібний, але справжній вихід інформації. Дешевше не показувати взагалі.

**Q: Сім запитів на кожне натискання — не занадто?**
A Тому дебаунс 300мс (один запит на слово, не на символ), ліміт 5, і п.3
технічних деталей: почати з трьох ресурсів і додавати після заміру.

**Q: Чи не дублює це пошук на сторінках?**
A Ні, вони для різного. Пошук на сторінці — «знайти серед міст», глобальний —
«знайти, не знаючи де». Тому «Показати всі N» веде саме на сторінковий пошук
(`?search=<q>`), передаючи адміна з одного інструмента в інший.

**Q: `Ctrl+K` не конфліктує з браузером?**
A У Chrome/Edge `Ctrl+K` фокусує адресний рядок для пошуку — `preventDefault()`
його перехоплює, і це загальноприйнята практика (GitHub, Linear, Slack). `/`
теж стандарт (GitHub). Але перевірити на Firefox, де `/` — вбудований
quick-find.
