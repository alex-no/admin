# Ядро — спільна логіка Vue і React

Чисті TS-функції без жодного імпорту з `vue`/`react` (і надалі — `@angular/*`),
які раніше були продубльовані окремо у `frontend/` і `frontend-react/`. Кожен
фронтенд і далі тримає свій стейт (`ref`/`useState`/майбутній Angular-сервіс)
і UI — ядро лише рахує, що покласти в URL/тіло запиту чи як відформатувати
значення, без жодної реактивності.

## Чому це тут

Дивись `../page-configs/README.md` — та сама причина: одна і та ж логіка,
задубльована вручну, розходиться непомітно для `vite build`/`tsc`. Конкретні
підтверджені дублі, які й стали першим наповненням ядра:

- `permissions.ts` — матчер прав (`'*'`, `'module.*'`) був побайтово
  ідентичний у `useAuth.js` (Vue) і `AuthContext.tsx` (React).
- `listQuery.ts` — збірка `URLSearchParams` з фільтрів/сортування/сторінки
  була повторена **тричі всередині кожного файлу** (основний запит, polling
  revalidate, CSV-експорт) в обох фреймворках.
- `sort.ts` — алгоритм цикла сортування. Тут знайшлася й реальна розбіжність:
  клік без модифікатора по спадній колонці при активному мультисорті в Vue
  скидав до одноколонкового `asc` саме на ній, а в React очищав сортування
  повністю. Канонічна поведінка — як була у Vue (проєктний eталон); React
  тепер поводиться так само.
- `phone.ts`, `csv.ts`, `exportFormat.ts`, `bulk.ts` — попарно ідентичні
  утиліти (`utils/phone.*`, `utils/csv.*`) і однакова форма bulk-запиту.

## Що свідомо лишилось поза ядром

Рендер (таблиця/ячейки/фільтри/модалки), сам стейт (`ref`/`useState`),
undo-toast UX, кешування довідників (`useRemoteOptions`) — все, що або прив'язане
до моделі реактивності конкретного фреймворка, або не було доведеним дублем.
Не додавайте сюди нічого "про запас" — лише те, що вже реально продубльоване.

## Напрямок сортування: 'asc' / 'desc'

Канонічне представлення в ядрі — рядки нижнього регістру (`SortItem.dir`).
У Vue внутрішній стан історично був `'ASC'`/`'DESC'` (великими) — це нікуди
не змінювалось за межами `DataListPage.vue`, конвертація в/з нижнього регістру
відбувається локально на межі виклику `toggleSort`, щоб не займатись міграцією
`SortIcon.vue`/`useUrlFilters.js`/інших сторінок, які ASC/DESC теж використовують,
але до ядра не мають стосунку. Бекенд приймає обидва регістри (`strtoupper`),
тож на API це не впливає.

## Тести

Автономні, без залежності від жодного з фронтендів:

```bash
cd shared/core
npm install
npm test
```

## Як підключено

Обидва `vite.config` мають alias `@core` → цей каталог, той самий механізм,
що й `@configs` (див. `../page-configs/README.md`). React додатково резолвить
`@core/*` через `tsconfig.json` → `paths`, бо `npm run build` = `tsc && vite build`.

## Правила

1. Сюди йде лише те, що вже реально задубльоване в обох фронтендах — не
   абстрактна "майбутня перевикористовуваність".
2. Жодних імпортів з `vue`, `react`, `@angular/*` чи DOM-фреймворкових API
   (крім vanilla `Blob`/`URL`/`document.createElement` у `csv.ts` — це звичайні
   браузерні API, однакові в будь-якому фронтенді).
3. Нова функція — новий/розширений `*.test.ts` поруч.
4. Якщо переносите існуючу логіку — спершу звірте обидві копії (Vue і React)
   рядок у рядок; якщо вони розійшлися (як у випадку `sort.ts`), розбіжність
   лишити явним коментарем із поясненням, яка поведінка стала канонічною і чому.
