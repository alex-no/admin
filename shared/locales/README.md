# Переклади — спільні для Vue і React

Тут лежать locale-файли (`uk.json`, `en.json`, `ru.json`) і барель `index.ts`
(`messages`, `availableLocales`, `LocaleCode`), які раніше були продубльовані
окремо у `frontend/src/locales/` (Vue, `vue-i18n`) і
`frontend-react/src/locales/` (React, `react-i18next`).

## Чому це тут

Та сама причина, що й у `../core/README.md` і `../page-configs/README.md`:
одна й та сама логіка/дані, задубльовані вручну, розходяться непомітно —
`vite build`/`tsc` цього не ловлять, бо обидва файли лишаються валідними.

## Розбіжність, знайдена при переносі (2026-08-07)

Одностороння: React мав на 5 ключів більше в кожній з трьох мов (React —
етало́н тут, бо саме там доробляли фічі й забули синхронізувати назад у Vue):

- `table.noHideableColumns`, `bulk.deleteWarning`, `dataList.apply`,
  `stoRegistry.photos.fileTooLarge`, `stoRegistry.photos.maxSize`
- увесь блок `theme.*` (`light`/`dark`/`auto`)

Конфліктних значень (той самий ключ — різний текст в обох копіях) не було.
Об'єднаний файл — просто об'єднання ключів, без втрати перекладів.

**Важливо:** ці ключі зараз реально використовуються тільки в React
(`t('theme.light')` у `TopNav.tsx`, `t('table.noHideableColumns')` у
`ColumnSelector.tsx` тощо) — перевірено `grep` по обох `src/`. У Vue
відповідні місця (перемикач теми, `ColumnSelector.vue`) або ще не переведені
на `vue-i18n`, або текст захардкоджений. Зайві ключі в Vue безпечні (просто не
використовуються), але якщо перекладаєте ці місця у Vue — ключі вже готові,
новий переклад не потрібен.

## Інтерполяція: `{var}`, не `{{var}}`

Канонічний синтаксис — одинарні дужки (`vue-i18n` за замовчуванням: `"Обрано {count}"`).
`react-i18next`/`i18next` за замовчуванням очікує **подвійні** (`{{count}}`) — з одинарними
просто не інтерполює, підставляючи рядок як є (`"Обрано {count}"` замість `"Обрано 5"`).

Виправлено конфігом, не рядками: `frontend-react/src/i18n.ts` перевизначає
`interpolation.prefix`/`suffix` на `'{'`/`'}'`. Тобто новий ключ з `{value}`
пишеться один раз і однаково працює в обох рендерерах — не треба пам'ятати
про подвійні дужки для React.

## Як підключено

Обидва `vite.config` мають alias `@locales` → цей каталог, той самий механізм,
що й `@core`/`@configs`. React додатково резолвить `@locales` через
`tsconfig.json` → `paths` (build = `tsc && vite build`).

Імпорт у коді — однаковий рядок в обох фронтендах:

```js
import { messages, availableLocales } from '@locales'
```

## Правила

1. Новий ключ перекладу додається тут, а не в `frontend/src/locales/` чи
   `frontend-react/src/locales/` — таких каталогів більше немає.
2. **Усі три мови (`uk`/`en`/`ru`) і всі ключі синхронні за визначенням** —
   тепер це один файл на мову, розійтись нема як.
3. Додав ключ, яким користується тільки один із фронтендів — це нормально
   (як `theme.*` вище): ядро не перевіряє, хто саме читає ключ, лише що
   ключ один для обох.
